{# Current fetch state of a feed, shared by the admin Feeds table and the admin dashboard's fetch-error list (Sources draws the same states as health dots, source_health in settings/partials/feeds_list.html). The state is read live from the feed row, so a feed that failed an hour ago but has fetched fine since shows as active — that is the point of putting it next to a logged error. The tooltips are written for whoever is looking, admin or subscriber: what the state means, whether it clears itself, and what happens next. They are a bonus for a mouse, never the only route to something — touch has no hover, so anything the reader actually needs to act on is spelled out in the row as well. with_count adds the counter behind the badge (consecutive refusals for throttled, consecutive failures otherwise). The Feeds tables leave it off: they spell the same thing out under the title, and a second word wraps their narrow column. threshold is how many consecutive refusals earn the throttled badge. The default guards lists that show healthy feeds too, where a lone 403 is noise. A caller whose rows are already there because something failed passes 1: in that company "active" next to a logged refusal reads as a contradiction, not as reassurance. The badge is the ui badge macro; the colours are the theme's status tokens (--rf-ok, --rf-warn, destructive, muted), never palette classes. The ok and warn badges keep foreground text: the status colours are too light for 12px text in light themes. #} {% from "ui/display.html" import badge %} {% macro status_badge(f, with_count=false, threshold=block_badge_threshold) %} {%- if f.status == 'active' and f.block_count >= threshold -%} {# Host is refusing automated requests: the warning colour, not destructive. The feed is fine and resumes on its own. See app/fetcher/failure.py for the two tiers. #} {%- call badge(variant="outline", attrs={"class": "whitespace-nowrap border-(--rf-warn)/50 bg-(--rf-warn)/10 text-foreground", "title": "The site is refusing automated requests. Nothing is wrong with the feed; fetching backs off and resumes on its own. Switched off after " ~ block_disable_threshold ~ " refusals."}) -%} throttled{% if with_count %} ×{{ f.block_count }}{% endif %} {%- endcall -%} {%- elif f.status == 'active' -%} {{- badge(text="active", variant="outline", attrs={"class": "border-(--rf-ok)/50 bg-(--rf-ok)/10 text-foreground"}) -}} {%- elif f.status == 'error' -%} {# No threshold quoted: the general one is 5 but a 404 disables after 4, and the feed row does not record which kind of failure it was. The count is exact, so state that and leave the number that would sometimes be wrong out. #} {%- call badge(variant="destructive", attrs={"class": "whitespace-nowrap", "title": "Last fetch failed" ~ (", " ~ f.fetch_error_count ~ " in a row" if f.fetch_error_count else "") ~ ". Fetching backs off and keeps retrying, and is switched off after repeated failures."}) -%} error{% if with_count and f.fetch_error_count %} ×{{ f.fetch_error_count }}{% endif %} {%- endcall -%} {%- elif f.status == 'disabled' -%} {# No "save the edit form to re-enable it" here: this macro renders in the admin tables, where the feed belongs to somebody else and /sources/feeds/{id}/edit is scoped to the current user. The subscriber gets that instruction in their own feed row, which only ever shows their own feeds. #} {%- call badge(variant="secondary", attrs={"class": "whitespace-nowrap", "title": "Fetching is switched off and will not retry on its own. Feeds are switched off automatically after repeated failures, and an admin can switch one off by hand."}) -%} disabled{% if with_count and f.fetch_error_count %} ×{{ f.fetch_error_count }}{% endif %} {%- endcall -%} {%- else -%} {{- badge(text=f.status, variant="outline", attrs={"class": "text-muted-foreground"}) -}} {%- endif -%} {% endmacro %}
